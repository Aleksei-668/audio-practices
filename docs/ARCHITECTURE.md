# Architecture

## Текущее состояние v2

В v2 проект переходит от структуры "страница сама знает про аудиофайлы" к структуре "страница отображает данные".

Основные слои:

- `public/audio` - физические аудиофайлы текущего MVP;
- `src/types` - TypeScript-типы предметной области;
- `src/data` - временный источник данных в коде;
- `src/app` - Next.js-страницы и компоненты интерфейса.

## Доменная модель

Главная сущность - `Practice`.

Практика описывает единицу контента, а не только аудиофайл. Сегодня это аудио, но модель оставляет место для видео, статей, программ, трекинга и рекомендаций.

Минимальная структура:

- `id` - стабильный идентификатор;
- `title` - название;
- `type` - тип контента;
- `contextId` - контекст использования;
- `description` - короткое описание;
- `media` - ссылка на медиа или будущий источник контента;
- `tags` - темы и признаки для фильтров и рекомендаций.

## Источник данных

На этом этапе данные хранятся в:

- `src/data/practices.ts`

Это осознанно простой слой. Его можно заменить на API, Supabase или CMS позже, если интерфейс будет продолжать работать с типом `Practice`.

## Поток данных

1. `src/data/practices.ts` экспортирует контексты и практики.
2. `src/app/page.tsx` импортирует данные.
3. `src/app/PracticePlayer.tsx` получает данные через props.
4. Компонент группирует практики по контекстам и отображает плеер.

## Что не делаем на этом шаге

- Не создаем админку.
- Не подключаем базу данных.
- Не меняем хранение аудиофайлов.
- Не добавляем авторизацию.
- Не добавляем трекинг, избранное и рекомендации в интерфейс.

## Следующие архитектурные шаги

1. Добавить отдельную страницу практики по `id`.
2. Добавить фильтры и поиск.
3. Выделить программы как отдельный тип данных.
4. Добавить пользовательские данные: избранное, история, прогресс.
5. Подключить ИИ-помощника к данным о практиках и состоянию пользователя.
