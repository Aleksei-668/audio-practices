# Roadmap

## 1. Текущий статус

Проект `audio-practices` уже работает как MVP: на сайте можно выбрать контекст и запустить аудиопрактику.

В ветке `v2` проект начал переходить от логики "сайт с аудиофайлами" к логике "платформа, построенная вокруг данных". Практики описаны как объекты `Practice`, а интерфейс получает список практик из `src/data/practices.ts`.

Текущая архитектура простая и осознанно локальная:

- аудиофайлы лежат в `public/audio`;
- данные описаны в коде;
- типы лежат в `src/types`;
- главная страница отображает данные через компонент плеера.

## 2. Ближайший этап

Ближайшая цель - аккуратно укрепить v2, не ломая MVP.

Что нужно сделать следующим:

- привести интерфейс к более ясной структуре;
- отделить отображение практик от бизнес-логики;
- подготовить сервисный слой для будущей замены локальных данных на API, Supabase или CMS;
- сохранить текущий сценарий: пользователь открывает сайт, выбирает практику и слушает аудио.

На этом этапе проект все еще может оставаться без авторизации, админки и базы данных.

## 3. Этап 1 — архитектура интерфейса

Цель этапа - сделать интерфейс устойчивым к росту количества контента.

План:

- выделить компоненты для списка контекстов;
- выделить компонент карточки практики;
- выделить компонент текущего плеера;
- подготовить место для будущих фильтров;
- продумать отдельную страницу практики;
- сохранить простую главную страницу без лишней сложности.

Результат этапа: интерфейс становится модульным, но для пользователя все остается привычным и работающим.

## 4. Этап 2 — сервисный слой

Цель этапа - убрать прямую зависимость страниц от конкретного файла данных.

План:

- создать функции получения практик;
- создать функцию получения практики по `id`;
- создать функцию получения контекстов;
- оставить `src/data/practices.ts` как текущий источник данных;
- сделать так, чтобы позже источник можно было заменить без переписывания интерфейса.

Возможная будущая структура:

- `src/services/practices.ts`;
- `getPractices()`;
- `getPracticeById(id)`;
- `getPracticeContexts()`.

Результат этапа: интерфейс работает не с местом хранения данных, а с понятными функциями.

## 5. Этап 3 — поиск и фильтрация

Цель этапа - помочь пользователю быстрее находить подходящую практику.

План:

- добавить поиск по названию и описанию;
- добавить фильтр по контексту;
- добавить фильтр по типу контента;
- добавить фильтр по тегам;
- позже добавить фильтр по длительности;
- не усложнять интерфейс раньше, чем появится достаточно контента.

Результат этапа: сайт становится библиотекой практик, а не просто списком аудио.

## 6. Этап 4 — избранное и история

Цель этапа - начать превращать проект в личный инструмент пользователя.

План:

- добавить возможность сохранять практики в избранное;
- добавить историю недавно прослушанных практик;
- сначала хранить эти данные локально в браузере;
- позже перенести их в пользовательский профиль;
- подготовить модель данных для прогресса.

Результат этапа: пользователь может возвращаться к своим практикам, а платформа начинает учитывать личный опыт.

## 7. Этап 5 — админка

Цель этапа - дать возможность управлять контентом без ручного редактирования кода.

План:

- определить минимальные поля для создания практики;
- добавить создание, редактирование и скрытие практик;
- добавить загрузку или привязку медиа;
- добавить управление тегами и контекстами;
- добавить предварительный просмотр;
- ограничить доступ к админке.

Важно: админку не делаем до тех пор, пока модель данных и пользовательский интерфейс не стабилизируются.

## 8. Этап 6 — облачное хранилище

Цель этапа - отделить медиафайлы от репозитория.

План:

- выбрать хранилище для аудио и будущего видео;
- перенести аудиофайлы из `public/audio`;
- обновить `media.src` в данных;
- продумать права доступа;
- продумать резервное копирование;
- подготовить процесс загрузки файлов через будущую админку.

Возможные варианты:

- Supabase Storage;
- S3-совместимое хранилище;
- специализированная CMS с медиа-библиотекой.

Результат этапа: репозиторий перестает быть местом хранения контента, а становится кодовой базой платформы.

## 9. Этап 7 — личная платформа развития

Цель этапа - расширить проект от аудиотеки до полноценной личной платформы.

План:

- добавить разные типы контента: аудио, видео, статьи, программы;
- добавить программы из нескольких практик;
- добавить личный профиль;
- добавить трекинг состояния и прогресса;
- добавить заметки пользователя;
- добавить рекомендации на основе истории и выбранных целей.

Результат этапа: пользователь получает не просто контент, а персональный маршрут развития.

## 10. Этап 8 — ИИ-рекомендации

Цель этапа - добавить ИИ-помощника, который помогает выбрать подходящую практику.

План:

- описать практики так, чтобы ИИ мог понимать их смысл;
- добавить цели, состояния и ограничения пользователя;
- сделать простой диалог выбора практики;
- подключить рекомендации к тегам, контекстам, истории и избранному;
- позже добавить объяснение рекомендации;
- не заменять человеческий выбор полностью, а помогать сузить варианты.

Примеры будущих сценариев:

- "У меня есть 5 минут, хочу мягко вернуться в тело";
- "Нужна практика после долгой работы сидя";
- "Хочу что-то спокойное перед сном";
- "Продолжи программу, которую я начал вчера".

Результат этапа: платформа становится внимательным помощником, а не только каталогом материалов.

## 11. Что пока НЕ делаем

На текущем шаге не делаем:

- админку;
- авторизацию;
- личные кабинеты;
- базу данных;
- облачное хранение;
- загрузку файлов;
- оплату;
- сложные рекомендации;
- ИИ-чат;
- новые зависимости;
- масштабный редизайн;
- перенос аудиофайлов;
- изменение текущего рабочего MVP.

Сейчас главный приоритет - спокойная архитектура, понятные данные и возможность развивать проект по шагам.
